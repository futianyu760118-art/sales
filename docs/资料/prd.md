## 2. 背景与目标

### 2.1 业务现状与立项动因

LED 光源板（面板灯/筒灯/线条灯等）的设计依赖人工完成 PCB 设计、BOM 整理、规格书与检验标准编制，周期长、易出错、知识沉淀在个人。立项动因是将「需求参数 → 意向方案 → 生产交付包」的完整链路系统化、自动化，缩短打样前设计周期，保证交付物一致性与可追溯性。

### 2.2 一期目标

以元器件资料库为底座、规则引擎为核心，实现从需求参数到生产交付包的闭环：

1. 用户输入结构/电气/材料/工艺参数后，系统自动生成意向方案（PCB 预览 + BOM + 成本估算）。
2. 方案确认后自动输出生产交付包：PCB 厂 Gerber/钻孔/拼板、贴片厂 BOM/坐标/工艺要求、设计源文件。
3. 一期成功标准：典型面板灯需求（18W / 24V / 2835 灯珠）从参数录入到拿到生产包 ≤ 1 个工作日（人工基线 ≥ 3 天）。

## 3. 范围与边界

### 3.1 一期（P0）范围

P0 共五个模块，另含支撑核心流程的方案确认与版本管理：

| 编号 | 模块 | 关键内容 |
|---|---|---|
| FR-1 | 需求参数录入 | 结构/电气/材料/工艺参数，合法性校验；DXF 导入仅占位 |
| FR-2 | 元器件资料库 | 常用料建库（2835/3030/5730/5050、连接器、电阻），含规格书/封装/替代料/电气参数 |
| FR-3 | PCB 自动生成引擎 | 板框 + 规则化 LED 阵列排布 + 半自动走线 + 铺铜 + 丝印 + DRC，输出 .kicad_pcb |
| FR-4 | 意向方案预览 | PCB 预览 + BOM 清单 + 成本估算 |
| FR-5 | 方案确认与版本管理 | 方案确认/拒绝、版本留痕、确认后锁定生成生产包 |
| FR-6 | 生产文件输出 | Gerber + 钻孔（Excellon）+ BOM + 坐标 + 拼板 + 设计源文件，打包下载 |

### 3.2 演进方向（本期明确不做）

- P1（二期）：规格书自动生成、检验标准自动生成（Word/PDF 模板引擎 + 国标/企标模板库）、DXF 结构导入（板框/孔位自动识别）。
- P2/P3（三期及以后）：驱动电路模板（恒流/阻容）、成本核算细化、AI 排布优化（光学均匀性）、热仿真集成。

### 3.3 范围外（明确声明）

- 全自动 PCB 任意走线：本期不做，一期为规则化阵列排布 + 半自动走线。
- LED 光学透镜/配光设计：不在本期。
- 一期交付包不含产品规格书与检验标准（属 P1 自动生成范围）；交付包目录结构为其预留位置。

## 4. 角色与核心流程

### 4.1 角色定义

| 角色 | 职责 | 主要使用功能 |
|---|---|---|
| 结构工程师 | 提出灯具结构约束，录入板外形/尺寸/安装孔位/禁布区域 | FR-1、FR-4（板框核对） |
| 电子工程师 | 提出电气与材料需求（电压/功率/色温/显色指数/光通量、板材/LED/连接器），评估并确认方案 | FR-1、FR-2（查询）、FR-3、FR-4、FR-5、FR-6 |
| 采购 | 查看 BOM 明细与成本估算，关注替代料与价格 | FR-2（查询）、FR-4 |
| 品质 | 验收生产交付包，为 P1 检验标准自动生成提供依据（本期仅使用数据底座） | FR-2（查询）、FR-6 |

### 4.2 核心业务流程

```
参数输入（结构/电气/材料/工艺）
  → 查库匹配（元器件库 + 工艺规则库）
  → 自动生成意向方案（PCB 预览 + BOM + 成本估算）
  → 用户确认（或调整参数重新生成）
  → 输出生产交付包（PCB 厂 Gerber/钻孔/拼板 + 贴片厂 BOM/坐标 + 设计源文件）
  → 打样 / 检验 / 量产
```

## 5. 用户故事与验收标准

### US-1 结构工程师录入结构需求

作为结构工程师，我希望录入板外形（矩形/圆形）尺寸、安装孔位与禁布区域，以便板框能匹配灯具结构的安装要求。

- 验收：支持矩形/圆形板框尺寸录入；支持多个安装孔（坐标 + 孔径）录入；支持禁布区域录入；必填项缺失时阻断提交并给出明确提示。

### US-2 电子工程师录入电气与材料需求

作为电子工程师，我希望录入电压/功率/色温/显色指数/光通量及板材、LED 封装、连接器、工艺要求，以便系统据此推算设计方案。

- 验收：全部参数项可录入且枚举值受控（电压：AC220V/DC12V/DC24V；板材：铝基板/FR4；LED 封装：2835/3030/5730/5050；连接器：2P 端子/3P 端子/排针；表面处理：喷锡/沉金/OSP；阻焊颜色：白/黑；拼板：不拼/V-cut/邮票孔）；非法值被拒绝并提示；功率与板面积匹配性校验给出可理解的警告或阻断。

### US-3 电子工程师获取意向方案

作为电子工程师，我希望提交需求后系统自动生成意向方案（PCB 预览 + BOM + 成本估算），以便快速评估方案可行性。

- 验收：提交需求参数后系统自动完成查库匹配、LED 数量与串并推算、排布计算并生成意向方案；方案包含 PCB 预览图、BOM 清单与成本估算三部分；LED 数量与串并方式满足电气约束（见 FR-3 验收标准）。

### US-4 电子工程师确认或拒绝方案

作为电子工程师，我希望确认方案后系统生成生产交付包，或在拒绝时保留原因并允许调整参数重新生成，以便方案可追溯。

- 验收：确认操作后方案状态变为「已确认」并锁定；拒绝操作记录拒绝原因且方案状态变为「已拒绝」，可基于调整后的参数生成新版本；历史版本可查询。

### US-5 采购查看 BOM 与成本

作为采购，我希望查看 BOM 明细（含位号/名称/规格/封装/数量/单价/内部料号/替代料）与成本估算，以便评估采购与成本风险。

- 验收：BOM 字段完整展示；单价取自元器件库；成本估算 = BOM 材料成本合计 + 加工费粗估，明细可核对（合计 = 各行之和）。

### US-6 电子工程师下载生产交付包

作为电子工程师，我希望确认方案后一键下载生产交付包，以便直接发给板厂与贴片厂。

- 验收：交付包为 zip，按「PCB 生产文件 / 贴片文件 / 设计源文件」三类目录组织；Gerber 各层、钻孔、BOM、坐标、拼板文件齐备；文件名含项目编号与日期；DRC 未通过时禁止生成（见 FR-3）。

## 6. P0 功能需求与验收标准

### FR-1 需求参数录入

功能点：

1. 结构参数：板外形（矩形/圆形）、板尺寸、安装孔位（数量/坐标/孔径）、禁布区域。
2. 电气参数：输入电压、总功率、色温、显色指数、光通量要求。
3. 材料参数：板材类型、板厚（0.8/1.0/1.6mm）、LED 封装、连接器类型。
4. 工艺参数：表面处理、阻焊颜色、拼板方式（不拼/V-cut/邮票孔）。
5. 参数合法性校验：必填校验、枚举校验、数值范围校验、功率与板面积匹配性校验（规则可配置，预置初版）。
6. DXF 导入：一期仅保留界面入口并标记「二期开放」，不实现解析。

验收标准：

- AC-FR1-1 全部参数项可录入、可保存，保存后可从历史需求中重新打开编辑。
- AC-FR1-2 任意必填项缺失、枚举值非法或数值越界时，提交被阻断且错误信息定位到具体字段。
- AC-FR1-3 功率与板面积匹配性规则（如单位面积功率上限）存在且可配置；触发时给出警告（可继续）或阻断（不可继续），行为由规则定义。
- AC-FR1-4 同一需求的参数变更产生新版本记录，旧版本可追溯。

### FR-2 元器件资料库

功能点：

1. 分类：LED、连接器、电阻、其他（分类可扩展）。
2. 基础字段：物料名称、规格型号、封装、制造商、制造商料号、内部料号、单价、状态（启用/停用）。
3. LED 特有电气字段：正向电压 Vf、正向电流 If、色温、显色指数 Ra、光通量——供串并计算与方案生成使用。
4. 资料关联：规格书附件、封装库文件、3D 模型文件、替代料关系（一对一/一对多）。
5. 管理操作：新增、编辑、停用、查询（按分类/名称/型号/封装过滤）。
6. 种子数据（开发阶段入库）：2835/3030/5730/5050 LED（含 Vf/If/色温/Ra/光通量/价格/替代料）、2P/3P 端子与排针连接器、常用电阻。

验收标准：

- AC-FR2-1 元器件增删改查可用；停用的元器件不出现在新方案匹配结果中，但历史方案 BOM 不受影响。
- AC-FR2-2 LED 电气字段（Vf/If/色温/Ra/光通量）为必填，缺省时该料不可被选作方案 LED。
- AC-FR2-3 替代料关系可维护，方案 BOM 中可展示替代料选项。
- AC-FR2-4 种子数据覆盖 2835/3030/5730/5050 四类 LED 各至少 1 条可用记录，且字段完整可参与计算。

### FR-3 PCB 自动生成引擎

功能点：

1. 板框生成：按结构参数生成矩形/圆形板框与安装孔位、禁布区。
2. LED 阵列排布：规则化阵列（行列数/间距/边距），自动避让安装孔与禁布区；排布参数由工艺规则库定义并可配置。
3. 电气连接（半自动走线）：按串并网络自动生成 LED 间及 LED 与连接器间的电气连接；常规网络自动走线，非常规连接允许在导出的源文件中手动调整；全自动任意走线不在本期。
4. 铺铜：规则化铺铜（电源/接地网络），参数可由工艺规则配置。
5. 丝印：位号、极性标记、版本标识。
6. DRC：按可配置规则（线宽/间距/孔径/丝印间距等）执行设计规则检查并输出报告。
7. 输出：.kicad_pcb 源文件（KiCad 生态，供后续导出 Gerber/Excellon/STEP）。

验收标准：

- AC-FR3-1 给定矩形/圆形板框与 LED 数量，生成规则阵列排布，排布不越界、不与安装孔/禁布区干涉。
- AC-FR3-2 LED 数量与串并方式由引擎依据元器件库 Vf/If 及输入电压、总功率自动推算，并满足：① 串联支路总电压 ≤ 输入电压 × 0.9（驱动余量，系数可配置）；② 计算功率（数量 × Vf × If）与需求功率偏差 ≤ 20%（阈值可配置）；③ 排布结果与串并结果写入方案数据。
- AC-FR3-3 串并网络正确：同支路 LED 依次串联，并联支路汇入电源网络，连接器正/负极正确接入；可由源文件或网表核对。
- AC-FR3-4 生成的 .kicad_pcb 可被 KiCad 打开，元件、网络、板框完整。
- AC-FR3-5 DRC 可执行并输出报告；DRC 存在错误（非警告）时，方案不可进入确认与生产文件生成。
- AC-FR3-6 DRC 规则（线宽/间距/孔径等）可配置且预置初版。

### FR-4 意向方案预览

功能点：

1. PCB 预览：板框 + LED 排布 + 走线 + 铺铜的 2D 预览图。
2. BOM 清单：位号、物料名称、规格型号、封装、数量、制造商、内部料号、单价、替代料。
3. 成本估算：BOM 材料成本合计 + 加工费粗估（基于板面积与工艺附加的简单模型，模型参数可配置）；估算结果标注「估算值，供参考」。

验收标准：

- AC-FR4-1 预览页同时呈现 PCB 图、BOM 表与成本估算，且三者数据同源于同一方案版本。
- AC-FR4-2 BOM 数量与排布结果一致（如阵列 N 颗 LED 对应 BOM 数量 N）。
- AC-FR4-3 成本合计 = BOM 各行小计之和 + 加工费，公式可核对。

### FR-5 方案确认与版本管理

功能点：

1. 方案状态机：生成（草稿）→ 已确认 / 已拒绝；确认后锁定。
2. 版本管理：每次基于参数的重新生成产生新版本，历史版本可查询、可对比（至少可查看）。
3. 拒绝原因记录。

验收标准：

- AC-FR5-1 确认后的方案参数与预览内容不可再被修改；如需变更必须生成新版本。
- AC-FR5-2 版本列表展示版本号、生成时间、状态、操作人，历史版本可查看详情。
- AC-FR5-3 只有「已确认」状态的方案可触发生产文件生成。

### FR-6 生产文件输出

功能点：

1. PCB 生产文件（板厂）：Gerber 各层（顶层铜/底层铜/丝印顶层/阻焊顶层/板框）、钻孔文件（Excellon）、拼板文件（如需求指定拼板）。
2. 贴片文件（贴片厂）：BOM 清单、贴片坐标文件（含转角）、元件位号图、工艺要求说明。
3. 设计源文件：.kicad_pcb（及可用时的 .kicad_sch、3D STEP）。
4. 打包下载：zip 按「01_PCB生产文件 / 02_贴片文件 / 04_设计源文件」目录组织，文件名含项目编号与日期；为「03_产品规格书与检验标准」预留目录位置（P1 填充）。

验收标准：

- AC-FR6-1 Gerber 文件为 RS-274X 标准格式，层齐全且层名与内容对应；钻孔文件为 Excellon 格式。
- AC-FR6-2 BOM 与坐标文件内容与确认方案一致（位号一一对应）；坐标文件含元件位号、X/Y、旋转角度等贴片必需字段。
- AC-FR6-3 拼板需求（V-cut/邮票孔）时输出拼板文件，否则不出。
- AC-FR6-4 交付包 zip 可正常解压，目录结构与命名规范符合约定，DRC 未通过的方案无法生成交付包。

## 7. 一期验收场景（端到端）

场景：18W / 24V / 2835 灯珠典型面板灯，从参数录入到拿到生产包 ≤ 1 个工作日。

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| 1 | 录入矩形面板灯需求：板尺寸（如 200×300mm）、DC 24V、18W、6500K、Ra≥80、光通量 ≥1800lm、铝基板 1.0mm、2835 LED、喷锡、白色阻焊、不拼板 | 参数通过校验并保存 |
| 2 | 提交生成方案 | 系统自动查库匹配、推算 LED 数量与串并、生成规则阵列排布；意向方案含 PCB 预览 + BOM + 成本估算；电气约束（AC-FR3-2）满足 |
| 3 | 电子工程师核对预览并确认方案 | 方案状态变为「已确认」；DRC 已通过（无错误） |
| 4 | 下载生产交付包 | zip 含 Gerber 全层 + 钻孔 + BOM + 坐标 + 源文件，文件齐备且格式符合板厂/贴片厂通用要求 |
| 5 | 全程计时 | 从参数录入到拿到生产包 ≤ 1 个工作日（含人工确认等待；系统自动处理时长 ≤ 30 分钟，见 NFR-1） |

验收判定：步骤 1~5 全部满足即一期验收通过；「生产文件可被板厂/贴片厂直接使用」由 QA 阶段以真实板厂/贴片厂格式要求做端到端校验（对应 TRIAGE_DECISION 中的高风险项）。

数据库：PostgreSQL，库名 `led_pcb_system`，约 20 张核心表（用户权限、项目、需求、方案/版本、元器件库、LED 知识库、PCB 规则库、模板库、BOM/生产文件/成本），DDL 由 architecture 阶段输出。

## 9. 非功能需求

- NFR-1 时效：典型面板灯需求端到端（含人工确认）≤ 1 个工作日；系统自动处理（提交参数 → 方案生成 → 确认后生成生产包）建议目标 ≤ 30 分钟，具体指标由架构阶段细化确认。
- NFR-2 可用性：Web 界面，支持研发小队成员（≤ 10 人规模）日常并发使用；具体并发指标由架构阶段确认。
- NFR-3 安全与权限：一期最小可用为登录 + 角色标识（结构工程师/电子工程师/采购/品质/管理员）；细粒度权限控制（如采购仅读 BOM 成本）列为 P1。
- NFR-4 可追溯性：需求、方案、版本、确认记录、生产文件生成记录全程留痕，可追溯。
- NFR-5 可移植性：PCB 源文件与生产文件遵循 KiCad 与行业通用格式（RS-274X/Excellon/CSV），不依赖专有工具。

## 10. 风险与依赖

## 11. 假设与开放问题

### 假设

- A1：一期不含驱动电路设计，LED 串并网络按「外部驱动供电」假设计算；串并约束（AC-FR3-2）以输入电压与 LED 电气参数为准。
- A2：成本估算口径为「材料成本 + 加工费粗估」，估算值仅供方案评估参考；细化（板材+加工+贴片+物流）在 P2。
- A3：一期交付包不含规格书与检验标准（P1 范围），目录结构为其预留。

### 开放问题（需相关方确认，不阻塞 PRD）

- OQ-1 项目/仓库绑定：由谁在何时完成绑定（最迟 development 阶段开始前）？（指向人工决策）
- OQ-2 MVP 排期：4~6 周建议工期是否确认？（指向项目发起人）
- OQ-3 串并计算驱动拓扑：规划文档示例「10 串 6 并」与 24V 直驱存在张力（10 串 × Vf ≈ 30V > 24V）；串并上限系数（0.9）与偏差阈值（20%）为默认值，最终规则以 architecture 阶段 ADR 确认的驱动拓扑假设为准。
- OQ-4 登录与权限：一期「登录 + 角色标识」的最小方案是否可接受，细粒度权限是否确认为 P1？
- OQ-5 PCB 引擎交互：半自动走线的「手动调整」以何种形式提供（系统内编辑 vs 导出 .kicad_pcb 后用 KiCad 调整后回传）？需架构阶段确认，影响 FR-3 验收方式。

## 12. 演进方向（本期不做，仅保留）

- P1：产品规格书自动生成、检验标准自动生成（Word/PDF 模板引擎 + 国标/企标模板库 + 参数匹配）、DXF 结构导入。
- P2：驱动电路模板（恒流/阻容）、成本核算细化。
- P3：AI 排布优化（光学均匀性）、热仿真集成。
