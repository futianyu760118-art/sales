# 产销协调会经营报告设计

## 目标

完善 S&OP 产销协调会模块的“稽核报告”和“部门报告”，使其适合会中投屏汇报，并支持从经营异常中勾选问题、批量形成 Action 待办。

## 用户场景

会议主持人选择当前 S&OP 周期并点击“生成本期报告”。系统展示经营总览、稽核结果和六个部门的核心指标；主持人查看异常候选，调整责任人、责任角色、优先级和截止日期后，批量生成 Action，随后在现有 Action 页面跟踪闭环。

## 报告内容与口径

报告周期沿用现有 S&OP 口径：上月 16 日至当月 15 日。报告采用管理层经营简报的阅读顺序，而不是先罗列部门明细：

1. 企业状态：按利润/经营结果、交付、供应、新品/研发四类展示红黄绿状态。当前系统没有真实利润数据时明确显示“未接入”，不得用缺失值推导经营状态。
2. 上期结果：以“指标、目标、实际、状态、来源/更新时间”为核心字段，展示准交率、预测达成率、异常关闭、采购齐套率、发货达成率等当前可计算指标，并标明与上期的环比变化；不具备可比口径时显示“不可比”。
3. 新变化雷达：展示新订单、新客户、新产品、新物料和新供应商等变化。若相应数据源未接入，保留雷达位置并标记“未接入/暂无数据”，不伪造变化数量。
4. 未来预测与风险：使用下一 S&OP 周期或未来 30 天中当前系统已有的可计算口径，展示订单/交付趋势、风险数和高风险数；每个风险需有来源、预测区间和可信度说明。
5. 稽核与部门详情：稽核报告包含到期事项数、完成数、完成率、上月完成率、环比变化、逾期/未完成项、持续项、未回复项和取数标准；部门报告包含销售、研发、计划、采购、品质、工程/仓库六个部门，每个部门返回核心指标、当前值、目标/标准、状态、数据来源和经营结论。

经营简报的结论区位于明细之前，至少回答“当前经营状态、上期结果、最新变化、未来风险、需要会议决策的事项”五个问题。详细稽核清单和六部门指标作为会中追问时展开的依据。

每个指标同时提供数据可信度元信息：来源、生成/更新时间、数据完整性或可信度、状态说明。可信度统一标记为“可靠、需核实、未接入”之一；缺少真实数据源的指标必须标记为“未接入”或“暂无数据”，不将缺失数据当成 0% 达成率。指标状态统一为正常、关注、异常或未接入，并使用中文显示。

## TOP 行动闭环

经营简报中的 TOP 行动不是普通任务清单，而是从“问题”到“结果验证”的闭环对象。每个异常候选在生成 Action 前至少呈现：问题、业务影响、原因/分析、建议方案、责任人、截止时间和结果验证方式；同时关联当前指标目标或会议取数标准，确保行动与当前经营目标一致。当前范围只实现报告展示和 Action 字段承接，不引入 Agent、Skills、Memory 或新的目标管理引擎。

## 异常候选与 Action

汇总接口返回可行动的异常候选，每项至少包含稳定候选标识、部门、问题描述、业务影响、原因/分析、建议方案、当前值/目标值、责任角色、建议优先级、建议截止日期、结果验证方式、目标/标准关联、数据来源、数据可信度和是否已有 Action。候选来源包括红灯 KPI、逾期/未完成稽核项、未解决预警、交付异常、采购短缺、产能瓶颈和部门异常指标。候选按影响和优先级形成会议 TOP 行动排序，并在页面上区分“需会议决策”和“可直接下发”。

页面允许全选、取消选择和逐项选择。批量生成前可编辑责任人、责任角色、优先级和截止日期；提交时复用现有 `POST /api/sop/actions` 接口，传入 `description`、`owner_name`、`owner_role`、`due_date`、`priority`、`meeting_id`、`issue_no` 和来源标识；问题、影响、原因、建议和验证信息合并保留在 Action 描述或扩展字段中，不能在批量创建时丢失。成功创建的候选显示“已生成”，重复点击不会重复创建。

## 技术方案

- 后端新增按 `period_month` 查询的会议报告汇总接口，统一计算经营总览、稽核结果、六部门指标和异常候选，减少前端拼接造成的口径分裂。
- 前端在现有“稽核报告”和“部门报告”页签顶部增加周期、生成时间和生成按钮；报告首屏采用适合投屏的企业状态、上期结果、新变化雷达、未来风险和 TOP 行动结论卡片，随后展示异常列表、稽核清单和部门指标卡片。
- 不新增报告快照表、不做 Word/PDF 导出；报告按当前周期实时生成。
- 汇总接口对单个数据源异常返回来源状态和说明，前端保留已有页面内容并提示异常；批量 Action 创建按条返回成功/失败结果。
- 保留现有会议管理、手工 Action 创建、Action 状态流转和既有报告接口。

## 数据质量修正

实现时校正会影响判断的现有口径：销售预测与实际必须明确计划维度；采购缺料数按实际缺料物料/数量计算，不直接用采购单总数代替；研发项目状态统一映射中文；品质数据未接入时明确标识而不是显示虚假的 0%。

## 验证

- 后端测试汇总接口在当前周期和指定周期下返回完整结构，且异常候选具备去重键和 Action 默认字段。
- 前端测试报告生成、中文状态渲染、缺失数据提示、勾选/批量提交和重复生成保护。
- 运行现有回归测试、Node 语法检查和 `git diff --check`；通过接口请求验证报告和 Action 创建链路。
