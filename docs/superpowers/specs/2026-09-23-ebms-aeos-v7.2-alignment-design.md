# EBMS 对齐 AEOS V7.2 架构整改设计 V1.0

- 状态：待 Owner 书面确认
- 日期：2026-09-23
- 适用仓库：`futianyu760118-art/sales`
- 上位基线：`futianyu760118-art/AEOS-`（AEOS V7.2）
- 目标模块：M03 EBMS 企业经营管理与决策系统

## 1. 目的与成功标准

本次整改将当前“综合经营单体系统”收敛为 AEOS M03 管理者主工作面，同时保护现有业务连续性。成功不以删除页面或拆出多个仓库为标准，而以以下结果为准：

1. EBMS 的责任边界被明确冻结，不再新增销售、研发、交付、财经等专业执行能力。
2. 当前能力均有唯一目标模块、事实源、迁移状态和 Accountable Owner。
3. 建立 Object/API/Event/Result/Exception/Decision/Action/Evidence 统一契约骨架。
4. 管理者闭环可表达为：Target → Result → Gap/Exception → Decision → Action → Result → Evidence → Review。
5. 跨域直接读表被登记、可观测并逐步替换为版本化 API/Event/Result；整改期间不破坏现有流程。
6. P0/P1 检查、测试和证据可重复执行。

## 2. 范围

### 2.1 本轮纳入

- 架构边界、模块映射、数据所有权和禁止扩展清单。
- 契约 Schema、示例、校验器和契约测试。
- 现有路由的领域清单与 Legacy/Transition 标记。
- M03 经营驾驶舱所需的 Result、Exception、Decision、Action、Evidence 聚合接口骨架。
- 跨域直读登记与迁移适配层。
- README、ADR、执行清单、CI Gate 和验收证据。
- 重复前端目录的事实核查与处置决定；未确认生产入口前不删除。

### 2.2 本轮不纳入

- 立即拆成多个仓库或微服务。
- 一次性迁移全部 JSON 数据到 PostgreSQL。
- 删除现有询价、客户、报价、订单、研发、采购、财务、IM 页面。
- 重写所有专业算法。
- 改变现有用户业务流程或生产数据。

## 3. 架构决策

采用“逻辑拆分 → 契约拆分 → API/Event 拆分 → Data Ownership 拆分 → 物理拆分”的渐进路线。

### 3.1 目标职责

| 能力 | 目标归属 | EBMS职责 |
|---|---|---|
| 目标、经营结果、异常、决策、行动、证据、复盘 | M03 | 事实聚合、决策与追踪 |
| 身份、组织、角色、权限、Agent/Skill/Memory | M01 | 只消费统一身份与策略 |
| 主数据、事件、证据、血缘 | M02 | 只通过契约访问 |
| 产品、项目、BOM、样品、技术转移 | M04 | 展示其 Result/Exception |
| 询价、客户、报价、定价、商务订单 | M05 | 展示其 Result/Exception |
| 物料、供应商、采购、交付检查 | M06 | 展示其 Result/Exception |
| 专业成本、费用、毛利核算 | M09 | 展示带算法版本的 Result |
| 外部 API、同步和连接器 | M11 | 调用连接器 |
| CI、测试、部署、可观测性 | M12 | 遵守 Gate |

S&OP/产销自治按 AEOS 总仓注册表中的 M03A 受控子模块处理，不并入通用 M03 专业算法。

### 3.2 M03 保留能力

M03 仅保留：

- Target/Plan
- Result
- Gap/Exception
- Decision
- Action
- Evidence
- Review
- 管理者 Dashboard/Report
- 跨域聚合查询与证据追溯

专业中心拥有业务对象写入权和专业算法事实源；M03 不复制定义第二套专业口径。

## 4. 契约设计

新增 `contracts/`，每类契约含 JSON Schema、示例和版本说明：

- `object/`
- `api/`
- `event/`
- `result/`
- `exception/`
- `decision/`
- `action/`
- `evidence/`

所有跨域消息必须包含：

- `contract_version`
- 全局唯一 ID
- `source_system`
- `source_object` 与 `object_id`
- `occurred_at` 与适用周期
- 状态和幂等键
- 关联 ID（如 decision/action/result/evidence）
- 口径或算法版本（涉及指标时）

Result 必须可关联 Evidence；Decision 必须可生成 Action；Action 完成必须产生 Result 或明确的失败结果；未经验证的 AI 输出不能升级为正式 Learning。

## 5. 数据所有权与兼容策略

新增 `architecture/DATA_OWNERSHIP.md`，每个数据集记录：

- 当前存储位置
- 当前写入者
- 目标模块与 Accountable Owner
- 权威事实源
- 消费方式
- 迁移阶段
- 技术债到期条件

迁移期间使用 Anti-Corruption Layer（ACL）包装旧 JSON 表。现有路由可继续运行，但跨域读取必须经适配器记录 source、consumer、purpose、contract version 和 deprecation status。禁止新增未登记的跨域直读。

财经指标必须由 M09 产生带 `calculation_version` 和 `evidence_ids` 的 Result；M03 不再新增第二套利润算法。

## 7. 数据流

1. 专业中心或 Legacy ACL 产生 Fact。
2. Fact 转为版本化 Event/Result/Exception。
3. M03 聚合结果和异常，不重算专业口径。
4. 管理者形成 Decision。
5. Decision 生成有 Owner、截止时间和验收规则的 Action。
6. Action 完成产生 Result。
7. Result 绑定 Evidence 并进入 Review。
8. 复盘结论经验证后才更新 Rule/Skill/Memory。

## 8. 错误处理与安全

- 契约校验失败：返回机器可读错误码，记录 trace_id，不写入正式结果。
- Evidence 缺失：Result 可标为 `UNVERIFIED`，不得显示为已验证结论。
- 重复事件：按 idempotency key 去重。
- 旧数据缺字段：由 ACL 补齐或明确标记 unknown，不伪造证据。
- 认证继续只信任 Bearer token；本轮不降低现有安全措施。
- 日志不得记录密码、token 或敏感证据正文。
- 所有迁移开关默认保持兼容路径，出现异常可回退到原路由。

## 9. 分阶段交付

### P0：边界冻结

- SYSTEM_BOUNDARY
- Current → Target Mapping
- Data Ownership
- Legacy Migration Register
- 禁止继续在 M03 扩展的能力清单
- ADR：渐进式拆分路线

### P1：契约与最小闭环

- 8 类契约 V1
- 校验器与契约测试
- Result/Exception/Decision/Action/Evidence 最小服务
- 至少一条端到端示范闭环
- CI 中的 schema/test gate

### P2：统一底座接入

- M01 身份/权限适配
- M02 数据与 Evidence 适配
- M04/M05/M06/M09 结果供给接口
- M11 Connector 抽离

### P3：消除直读与物理拆分准备

- 移除已替代的跨域直读
- 数据库扩展方案
- 仓库/服务拆分决策
- UAT 与 Owner Verify

## 10. 测试与验收

最低验收集：

1. 契约 Schema 正例和反例测试。
2. Decision → Action → Result → Evidence 关联完整性测试。
3. Event 幂等与重复提交测试。
4. Legacy ACL 兼容回归测试。
5. 鉴权和敏感字段日志测试。
6. 现有关键路由 smoke test。
7. Docker 启动和 health check。
8. 端到端示范：一个真实经营异常形成决策、行动、结果与证据。

P0/P1 完成条件：

- 映射和所有权无未解释冲突。
- 新增跨域接口全部通过契约校验。
- 现有关键流程无回归。
- CI Gate 通过。
- Evidence 包含测试输出、提交 SHA 和 Owner Verify 记录。

## 11. 迁移与回滚

- 以功能开关启用新聚合/契约路径。
- 旧路由在替代验收前保持可用并标为 Legacy。
- 每个迁移项必须有 owner、替代接口、验收证据和移除条件。
- 若新路径失败，关闭开关恢复旧路径；不执行不可逆数据转换。
- 删除重复目录或旧模块必须单独提交，并在生产入口和回归测试确认后进行。

## 12. 约束

- 先边界、后功能；先闭环、后扩展。
- 代码完成不等于业务完成。
- PR 合并不等于业务完成。
- 每个模块和数据集只有一个 Accountable Owner。
- 任何临时跨域直连必须登记技术债、Owner 和到期条件。
- 本设计不得被解释为授权立即删除现有生产功能。
